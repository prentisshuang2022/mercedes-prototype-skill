# 真实界面实测

来源是用户在奔驰内部系统上的截图。**每个数字都标注来源等级**,不要把估读值当成规范:

- **实测**:截图里 DevTools 样式面板直接显示的值。
- **估读**:从截图像素量出来的近似值,缩放比例按 1:1 假设,误差约 ±2px。
- **推断**:截图里只看到变量名或框架,数值来自框架默认值,**没有在截图里验证**。

## 截图 3:发起流程表单(有 DevTools)

| 项目 | 数值 | 来源 |
|---|---|---|

结论:系统是 **Element Plus**。统一控件高度 32px、14px 字号、4px 圆角,是这个框架的默认体系,不是设计师随手定的值。

## 取舍(落到令牌里的值)

| 令牌 | 值 | 依据 |
|---|---|---|
| `--control-h` | 32px | 实测 |
| `--control-h-sm` / `--control-h-lg` | 24px / 40px | 推断(Element Plus 尺寸);门户搜索药丸约 40,估读也吻合 |
| `--radius` | 4px | 推断(Element Plus 基础圆角) |
| 下拉内边距 | 左 12 / 右 32,箭头 16px 距右 10px,文字与箭头间 6px | 左 12 与间距 6 来自实测;右 32 是为容纳 16px 图标反推 |
| `--radius-card` | 8px | 估读(门户卡片、方块卡片两处一致) |
| `--radius-group` | 16px | 实测 15px,吸附到 16 以对齐刻度 |
| 容器内边距 | 16 | 估读(卡片、方块一致) |
| 卡片网格间距 | 列 16 / 行 24 | 估读 15 / 23,吸附到刻度 |
| 表单行距 | 沿用刻度值,不追 20 | 估读;20 在刻度上,但行内边距 8+8 更紧凑,先不改 |

**仍然没有验证的**:Element Plus 圆角变量的真实值;按钮的真实字重(Element 默认中等,本 skill 只有 400 / 700);表格行高、表头样式、标签页细节。拿到这些页面的 DevTools 截图后再校准。

## CMP 原型的前后对比(变更列表页)

| 项目 | v4(改之前) | v5 |
|---|---|---|
| 控件高度 | 23、31、32、35、36、48 等 **8 种** | **32 一种** |
| 控件字号 | 12 与 14 混用 | 14 |
| 控件圆角 | 2px | 4px |
| 搜索框 | 灰色外框里套白色原生输入框(高 23) | 单层 32px |
| 表格状态色条 | 离表格边缘 12px,固定 52px 高 | 贴边,通栏 |

根因不在样式数值本身,而在多层样式叠加:`.btn` 同时有 40、36、32 三套高度;一条 `!important` 的"紧凑"规则把 `.btn.sm` 压回 12px;`input:not([type=checkbox])` 给搜索框内层强加了白底;`table.grid td` 的内边距盖住了 `td.sev` 的 `padding:0`。
